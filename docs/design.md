# SpaceSweep 首版设计

## 使用场景

默认完成一轮多盘清理。Agent 要找齐范围内能核实、值得清的项目，说明取舍，执行获批计划并核对实际结果。扫描范围和授权以[清理边界](boundaries.md)为准。

| 用户请求 | 工作方式 |
| --- | --- |
| 「把电脑里能清的都清一遍」 | 逐盘跑完所有适用规则。追查可能漏掉的有意义的大项，生成跨盘预览。低代价且已验证的候选纳入建议，高代价候选和应用内处理机会带上影响供用户选择。 |
| 「帮我看看空间被什么占了」 | 只读查看按盘、按应用和目录的占用。优先定位最大的几项，给出归属、证据、路径和报告能覆盖的范围。 |
| 「帮 C 盘再腾出 20 GB」 | 用户提出容量目标时按该卷计算。区分希望增加的量和最终可用空间门槛。按预估收益与影响挑选方案，执行后检查目标与实测的差距。 |
| 「昨天清完，今天怎么又少了」 | 有两份范围和统计口径可比的本地扫描时，找出增长最多的应用与目录。第一次扫描建立基线。核实反复重建后，再给出应用支持的长期管理方式。比如 After Effects 可设置磁盘缓存容量上限。 [Adobe 磁盘缓存设置](https://helpx.adobe.com/after-effects/desktop/get-started/preferences-and-settings/preferences.html) |

### 按真实场景交付

| 场景 | 阶段目标 |
| --- | --- |
| 日常整轮清理 | 一轮扫描发现各盘的回收站、临时文件、系统垃圾和常见应用缓存。尽早给出主要发现，按应用和类别展开预览。CCleaner 提供整轮 Health Check 和可展开的 Custom Clean。 [CCleaner](https://support.ccleaner.com/s/article/how-do-i-use-custom-clean?language=en_US) |
| 系统盘空间告急 | 给出目标盘上实际可处理的项目、预计收益和处理后的可用空间。对旧 Windows 安装等系统管理项，报告对应的 Windows 清理入口。 [Windows 清理建议](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/free-up-drive-space-in-windows) |
| 大型应用与数据盘 | 定位浏览器多配置、迁移后的应用数据、剪辑媒体缓存、游戏下载缓存和开发工具缓存。按真实位置和用途说明重建、重下或登录影响。 [Premiere](https://helpx.adobe.com/premiere/desktop/troubleshooting/media-issues/clear-media-cache-using-preferences.html) · [Steam](https://help.steampowered.com/en/faqs/view/6AD7-820D-8BE5-E51F) · [Docker](https://docs.docker.com/reference/cli/docker/system/prune/) |

使用成熟清理软件的日常流程和规则库确定覆盖类别。共享的缓存布局用同一识别方式覆盖多个应用和数据盘。用整轮新增发现的条目、体积、可处理范围和用时验收。 [BleachBit CleanerML](https://docs.bleachbit.org/cml/cleanerml/) · [Winapp2](https://github.com/MoscaDotTo/Winapp2)

## 职责与调用

本地执行器首选 Rust CLI。由标准库做常规文件枚举，用 Microsoft 的 Windows API 绑定获取卷信息和文件句柄。C# 和 .NET 10 LTS 保留为备选。 [Rust 目录项元数据](https://doc.rust-lang.org/std/fs/struct.DirEntry.html#method.metadata) · [Microsoft Windows Rust 绑定](https://github.com/microsoft/windows-rs)

| 位置 | 职责 |
| --- | --- |
| Rust 执行器 | 枚举卷，定位应用数据，读取元数据，持续汇总并输出 JSON。校验规则和清理计划，在文件系统层面落实边界。 |
| 应用规则 | 建议用项目随附的 TOML 描述软件版本、数据路径、匹配条件、动作和影响。新增常规应用只需补验证过的规则。定位确需专用逻辑时加小的 Rust 只读适配函数。参见[规则与应用覆盖](application-rules.md)。 |
| 运行时 `SKILL.md` 和 Agent | 从请求读出范围、保留条件和用户需要的结果，决定下一次读什么、如何解释证据。依据候选编号形成计划，拿到用户授权后调用执行器。识别不出的应用可继续调查，用于解释和提出待验证规则。 |
| Windows 或应用 | 掌握同步状态、应用索引、下载任务和素材引用关系时，通过各自的管理入口操作。Agent 可说明操作位置、影响和复测结果。 |

首版采用三个入口。名字和参数在首次实现时以实际 CLI 为准。

| 入口 | 输入 | 输出 |
| --- | --- | --- |
| `scan` | 默认本地全部卷。可指定卷或目录以及快速检查或目录分析。 | 扫描编号和 JSON 摘要。包含实际卷、容量、检查范围、应用用量、规则候选、重点目录以及跳过项。 |
| `plan` | 本轮扫描的候选编号和用户选择。一次计划可汇总多次定向检查发现的候选。 | 去重后的本地计划及预览。包含计划编号、每个条目的处理方式、收益估算和影响，记录可执行项的规则版本及目标身份。 |
| `apply` | 用户已确认的计划编号。 | 逐项的删除、跳过、失败或取消状态，每个受影响卷的前后容量和净变化。 |

结构化数据内的空间量统一用字节，摘要显示单位和统计口径。候选至少关联卷、应用或文件来源、规则及其版本、估算方法和建议处理方式。用明确的状态区分有资格执行的计划项目、待用户检查的发现和应用内入口。完整清单放本机，摘要可只列最有收益的组。

## 日常多盘清理流程

1. **先找垃圾。** 逐盘查回收站与已知的诊断产物、可重建缓存和陈旧临时文件。需要完整检查时，用同一次目录遍历找散落的临时产物。先汇报识别出的对象和体积，再处理发现缺口。
2. **追查缺口。** 对结果中的大项、未知归属和常见遗漏来源定向分析。看实际位置、目录构成、应用安装信息与官方文档。优先检查可能显著增加可处理范围的位置。报告标明每卷查过的范围、跳过原因及仍待查的位置。
3. **给出选择。** 将范围内已验证、重建代价低的候选纳入完整预览。针对确有收益的可选项，说明来自哪个盘、预计多少、成本和谁来操作。用户可以排除特定应用或项目，再确认一份计划。
4. **执行并复测。** 处理整个已确认的计划，按盘报告实际可用容量变化和各项结果。列出仍值得处理的项目及原因，例如需要应用内操作、当前占用或用途待核实。

日常流程以完成范围内适用检查和获批计划作为结束条件。用户提出容量目标时，再按目标盘核算收益。用户明确要求复用的保留偏好可记录在本地。遇到占用明显的新应用时，整理应用及版本、真实目录、厂商资料、影响和验证办法，供后续形成可发布规则。

## 性能与空间口径

- 先做范围明确的流式枚举。尽量一次遍历取得属性、长度和时间，同时计算规则命中、目录用量和最大的若干文件。同一批规则共享目录遍历。只为进入计划的条目补查文件身份和必要的分配量。
- 从单个扫描工作线程起步。按卷分批给进度和取消机会，同一物理盘上的卷共享 I/O 压力预算。记录首批结果耗时、总耗时、CPU、磁盘负载和峰值内存，再根据实测调整。冷、热缓存用同一台设备和同一范围比较。
- 默认扫描以元数据为主。重复内容检测在用户选定范围后按需进行，先按大小分组，再读取仍需校验的文件。全盘通用枚举成为实测瓶颈后，再评估对 NTFS 主文件表的优化。 [Czkawka 分阶段去重](https://github.com/qarmin/czkawka/blob/master/instructions/Instruction_Core.md#duplicate-finder) · [WinDirStat 的 MFT 扫描](https://github.com/windirstat/windirstat/blob/master/CHANGELOG.md)
- 目录图按文件长度合计。清理预览在能低成本取得时参考磁盘分配量，按实际所在卷估算并去重。执行后用同一口径读卷的前后可用空间，报告净变化和成功操作的文件长度合计。后台活动也会反映在卷的净变化里。 [文件分配量](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_standard_info) · [卷可用空间](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw)

## 报告样式

Skill 通过同一会话输出[本地 HTML 报告](usage.md#本地可视化报告)和简短结论。容量卡标明快查、选定目录、整卷时限或跳过情况，下方展示已读范围内的目录排行。预览给主要候选、预计占用和影响，执行报告给逐盘的前后容量、净增量和处理状态。 [WinDirStat 展示示例](https://windirstat.net/)

示意。C 盘的可用空间增加了 1.2 GiB，D 盘增加了 8.2 GiB。另有 12 项被占用，6 项在预览后变动。E 盘有一份核实到的媒体缓存，适合从应用内确认清理范围。

## 实现顺序与验收

1. **只读原型。** 先验证 Windows 11 本地 NTFS。Rust 能列出多个卷，输出按卷的容量和范围清单，对目录进行分析并说明未访问原因。用可控样本测多盘、同卷的多个入口和迁到数据盘的应用配置。QQ、微信优先做只读用量识别。
2. **清理试点。** 用旧临时文件和一种浏览器网页磁盘缓存打通预览和永久删除。用另一类应用案例检验规则和展示复用。测试临时目录中混合有效候选、隐藏内容、占用、联接点、硬链接、预览后替换、取消及重跑。在用户确认过的计划上逐项核对结果。
3. **优先完善垃圾发现。** 主验收用「所有盘，尽量把垃圾找齐」。样本同时有多个盘的生成数据、迁移的缓存、普通用户文件和应保留的资料。用同一范围对照成熟工具，记录各类垃圾的发现数量、大小、漏项、误判、首批结果用时和最终用时。全盘枚举数用于说明覆盖。
4. **按实测扩展。** 优先补上漏掉的垃圾来源和常用应用。对可查清用途的候选完善清理预览和执行。 [规则与应用覆盖](application-rules.md)
